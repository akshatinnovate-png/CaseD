# cased2.0

### You shipped it. Now make the trailer.

**cased2.0** reads your repository and renders a cinematic launch film —
score, motion, beat-matched cuts, and share copy — from one command.

No API keys. No cloud render. No bundled music. Nothing to subscribe to.

## What it does

Point it at a repo. It reads the git history, the language mix, the architecture
and the actual source, finds the story in there, writes a soundtrack to match,
cuts the picture to the beat, and renders an MP4.

```bash
python3 -m cased .
```

That's the whole interface. A few minutes later you have twenty-four seconds
of film, a soundtrack, and the copy to post with it.

## What makes it different

Most launch-video tools ask for a URL and screenshot it. cased2.0 reads the work.

- **It reads the repository, not a webpage.** Commit history, churn, language
  breakdown, test coverage, entry points, dependency count. The numbers on
  screen are measured from your code, never invented.
- **Real source appears on screen.** It scores every file for on-screen appeal,
  picks the most photogenic contiguous slice, and types it out syntax-highlighted.
- **The soundtrack is generated, not licensed.** A full arrangement — drums,
  sub bass, Karplus-Strong plucks, pad stack, risers, sidechain compression —
  synthesised from scratch in the standard library. Your film has music nobody
  else has.
- **Every cut lands on a beat.** The scorer picks the tempo first and hands back
  a beat map. The editor snaps every shot boundary to it. That one constraint is
  most of the difference between a slideshow and something that feels edited.
- **Frame-stepped, not screen-recorded.** The renderer calls `seek(t)` for each
  frame and screenshots the result, so a slow laptop and a CI runner produce the
  same file. No dropped frames, ever.
- **Same seed, same film.** Reproducible end to end.
- **Six directors.** One repo, six completely different films.
- **Ships every aspect ratio.** 16:9, 9:16, 1:1, 4:5, plus a GIF, a poster frame
  and post-ready copy for X, LinkedIn, HN and Product Hunt.

## Install

cased2.0 is Python 3.9+ standard library, plus Node and FFmpeg for the render.

```bash
git clone https://github.com/akshatinnovate-png/CaseD
cd CaseD
npm i -g playwright && npx playwright install chromium   # one time
python3 -m cased /path/to/your/project
```

Requirements: **Python 3.9+** · **Node 18+** · **FFmpeg** · **Chromium** (via Playwright).

## The directors

A director is a complete point of view: palette, background bed, pacing,
transition vocabulary, and the musical mood underneath. Same repo, six films.

| Director | What it looks like |
|---|---|
| `cinematic` | Deep blacks, slow pushes, letterbox. Takes the work seriously. **(default)** |
| `brutalist` | Hot pink, hard cuts, dialog boxes, type the size of a bus. |
| `terminal` | Phosphor green, scanlines, code first. For things with a prompt. |
| `hype` | Flash cuts, glitch, neon. Built to stop a thumb mid-scroll. |
| `orbit` | Starfield, a turning globe, long arcs. For things that ship wide. |
| `warm` | Soft light, unhurried, generous margins. Quietly confident. |

```bash
python3 -m cased . --director brutalist
python3 -m cased . --director orbit --format 9:16 --gif
```

Leave `--director` off and cased2.0 picks one from what your repo actually is —
a CLI gets `terminal`, a service gets `orbit`, a renderer gets `hype`.

## How it works

Four stages. Each one writes its output to disk, so you can inspect or hand-edit
any of them and re-run the next.

```
  analyze     repo          ->  story.json    what this project actually is
  score       duration      ->  score.wav     a soundtrack + the beat map
  compose     story + map   ->  spec.json     the shot list, cut to the beat
  render      spec          ->  cased.mp4     frame-stepped capture -> FFmpeg
```

`--plan-only` stops after `compose`, so you can read the edit before paying for
a render. Edit `spec.json` by hand and re-render it directly if you want to
direct it yourself.

```

├── story.json         everything the analyzer found
└── spec.json          the full edit, re-renderable
```

## Options

```
python3 -m cased [path] [options]

  -d, --director NAME     cinematic | brutalist | terminal | hype | orbit | warm
  -t, --duration SECONDS  runtime (default: 24)
  -f, --format SPEC       16:9 | 9:16 | 1:1 | 4:5 | all   (comma-separated ok)
  -q, --quality LEVEL     draft | good | high              (default: high)
  -o, --out DIR           output directory  (default: cased-output)
      --seed N            same seed, same film
      --url URL           override the link on the end card
      --tagline TEXT      override the headline
      --gif               also emit a looping GIF
      --no-audio          render silent (cuts still follow the beat map)
      --plan-only         write the plan and stop
      --list-directors    show every director
```

### Quality presets

The stage always renders at full size; the preset decides what gets encoded.

| Preset | Output width | CRF | Use it for |
|---|---|---|---|
| `draft` | capped at 960 | 28 | iterating — about 2× faster to encode, same frame cost |
| `good` | capped at 1280 | 23 | READMEs, social, anything that has to be downloaded |
| `high` | native (1920) | 19 | the master you upload (**default**) |

A cap is never an upscale, so vertical formats keep their native width.

Film grain is expensive to encode — it is uncorrelated noise over the whole
frame. cased2.0 holds the grain for two frames rather than redrawing it every
frame, which is how real film grain reads anyway and roughly halves the file.

## Honest limitations

- **Rendering is CPU-bound.** There is no GPU in most CI containers, so WebGL
  runs on SwiftShader. Expect roughly 3–5 minutes for a 24-second 1080p film on
  a typical machine. Use `--quality draft` while you iterate.
- **The analyzer wants a git repository.** It works without one, but the history
  beats — commit counts, milestones, churn — will be missing.
- **Fonts are system fonts.** cased2.0 deliberately embeds no typefaces, so the
  film uses the Helvetica/Arial/Liberation stack available on the host. Identical
  within a platform; very slightly different across them.
- **The synthesised score is a score, not a song.** It is built to sit under a
  voiceover-free 24-second film and get out of the way.

## Developing

```bash
python3 scripts/selftest.py          # full — renders a real 2.5s film
python3 scripts/selftest.py --fast   # skip the render stage
python3 scripts/sync_bed.py          # after editing the shader in stage.html
```

The self-test asserts the invariants that are easy to break by accident:
shots tile the runtime with no gaps, every cut lands on a beat, the audio is
neither quiet nor clipped, and analysis, scoring and composition are all
reproducible from the seed.

If you edit the fragment shader in `cased/engine/stage.html`, re-run
`scripts/sync_bed.py` — CI fails if the site's copy has drifted.

### Publishing the site

CI deploys `docs/` to GitHub Pages on every push to `main`, but Pages has to be
switched on once by a repository admin first:

**Settings → Pages → Build and deployment → Source: _GitHub Actions_**

This genuinely cannot be automated from the workflow. Creating a Pages site
needs admin rights, and `GITHUB_TOKEN` does not have them at any `permissions:`
level — `pages: write` grants deploying to a site that already exists, not
creating one. Until it is enabled, the deploy job fails with
`Get Pages site failed: Not Found`; the self-test job is unaffected.
