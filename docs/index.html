01 / what it does

Most tools screenshot a webpage. This one reads the work.

01

It reads the repository

Commit history, churn, language breakdown, entry points, test coverage, dependency count. Every number on screen is measured from your code — never invented.

02

Real source on screen

It scores every file for on-screen appeal, finds the most photogenic contiguous slice, and types it out syntax-highlighted.

03

The score is synthesised

Drums, sub bass, Karplus-Strong plucks, a pad stack, risers and sidechain compression — generated from scratch in the standard library. Music nobody else has.

04

Every cut lands on a beat

The scorer picks the tempo first and returns a beat map. The editor snaps every shot boundary to it. That constraint is most of the difference between a slideshow and an edit.

05

Frame-stepped, not recorded

The renderer calls seek(t) per frame and screenshots it. A slow laptop and a CI runner produce the same file. No dropped frames, ever.

06

Same seed, same film

Reproducible end to end — analysis, arrangement, edit and render. Change the seed to roll a different cut of the same story.

02 / directors

One repo. Six films.

A director is a complete point of view — palette, background bed, pacing, transition vocabulary and the musical mood underneath. Hover one; it's running the renderer's own shader, live.

03 / how it works

Four stages. All inspectable.

Each stage writes its output to disk. Read it, hand-edit it, re-run the next one. Nothing is a black box.

  1. 01

    analyze

    repo → story.json

    Walks the tree and the git log. Finds the hero language, the busiest file, the milestones, and the slices of source worth showing.

  2. 02

    score

    duration → score.wav

    Picks a tempo and a key, arranges intro/build/peak/resolve, synthesises every voice, and returns the beat map the edit is cut to.

  3. 03

    compose

    story + map → spec.json

    Chooses which beats this repo has earned, allocates runtime, then snaps every cut onto the beat grid and section impacts.

  4. 04

    render

    spec → cased.mp4

    Steps the scene engine frame by frame through headless Chromium and pipes the result straight into FFmpeg.
